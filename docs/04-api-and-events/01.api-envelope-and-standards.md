# 04.1. Chuẩn Hóa Phản Hồi API & Mã Lỗi (API Envelope & Standards)

## 1. Cấu Trúc Bao Đóng Thống Nhất (`ApiResponse<T>`)

Mọi phản hồi từ hệ thống RESTful API đều tuân thủ cấu trúc envelope:

```json
{
  "success": true,
  "message": "Thông điệp phản hồi kết quả",
  "code": "MÃ_LỖI_NẾU_CÓ",
  "data": { ... },
  "timestamp": "2026-11-18T04:20:00.000Z"
}
```

---

## 2. Bảng Quy Chuẩn Mã Lỗi Hệ Thống

| HTTP Status | Mã Lỗi (`code`) | Ý Nghĩa Nghiệp Vụ & Hướng Xử Lý |
| :--- | :--- | :--- |
| `200 OK` | `null` | Yêu cầu xử lý thành công hoàn toàn |
| `400 BAD_REQUEST` | `VALIDATION_FAILED` | Dữ liệu đầu vào vi phạm ràng buộc Jakarta Validation (`@Valid`) |
| `400 BAD_REQUEST` | `SEAT_ALREADY_RESERVED` | Ghế đã có người khác giữ hoặc mua trước |
| `400 BAD_REQUEST` | `INVALID_CREDENTIALS` | Tên đăng nhập hoặc mật khẩu không chính xác |
| `404 NOT_FOUND` | `NOT_FOUND` | Không tìm thấy thực thể tương ứng (Trip, Booking, Payment) |
| `405 METHOD_NOT_ALLOWED` | `METHOD_NOT_ALLOWED` | Gọi sai HTTP Method (VD: Gửi GET vào endpoint POST) |
| `500 INTERNAL_ERROR`| `INTERNAL_SERVER_ERROR` | Lỗi máy chủ ngoài dự kiến |
